# 蓝图炮 Schematicannon — 使用文档

一个还原机械动力（Create）蓝图炮玩法的 NeoForge 模组，单方块实现，附带蓝图桌、蓝图与笔和材料清单。直接在界面里选 `.nbt` 原理图就能打印，不需要额外的蓝图物品。

主要特性：逐层逐块打印、**缺料可跳过继续打**、**创造模式玩家开炮免材料**、**自动从相邻箱子取材料**、**输出材料清单道具**（右键查看已收集/未收集）、**半透明结构预览**（实时渲染待打印的结构，打完一块少一块）、**蓝图与笔选区实时高亮**、**打印朝向可旋转 / 水平翻转**。

- 模组 ID：`schematicannon`
- 版本：1.0.0
- 游戏版本：Minecraft 26.1.2
- 加载器：NeoForge 26.1.2.112 及以上
- 交付文件：`schematicannon-1.0.0.jar`

---

## 1. 安装

1. 安装 NeoForge 26.1.2.112+（自带 Java 25 要求，需 JDK 25 运行游戏）。
2. 把 `schematicannon-1.0.0.jar` 放进游戏目录的 `mods/` 文件夹。
3. 启动游戏。创造模式物品栏会出现一个新的分类页 **蓝图炮**，里面有 4 个物品。

服务端与客户端都需要装（这是有方块实体和网络包的模组，不是纯客户端模组）。

---

## 2. 内容一览

| 名称     | 类型 | 说明                                                                      |
| -------- | ---- | ------------------------------------------------------------------------- |
| 蓝图炮   | 方块 | 右键打开 GUI，选择 `.nbt` 原理图并逐块打印                                |
| 蓝图桌   | 方块 | 把蓝图与笔标记的区域保存成 `.nbt` 文件                                    |
| 蓝图与笔 | 物品 | 右键选两个角来标记一个长方体区域；**可重复使用，不会被消耗**              |
| 材料清单 | 物品 | 由蓝图炮的「输出清单」按钮生成；**右键打开**查看每种材料的需求数 / 已有数 |

两个方块的物品形态直接显示各自的 3D 方块模型（与原版方块一致），蓝图与笔是手绘的 2D 图标（图纸 + 羽毛笔），材料清单是 2D 图标。

### 合成配方

全部在原版工作台里合成，配方文件在 `src/main/resources/data/schematicannon/recipe/`。

| 产物     | 类型     | 配方                            |
| -------- | -------- | ------------------------------- |
| 蓝图与笔 | 无序合成 | 铁锭 ×1 + 青金石 ×1             |
| 蓝图炮   | 有序 3×3 | 原木 ×2 + 煤炭块 ×5 + 红石块 ×1 |
| 蓝图桌   | 有序 3×3 | 工作台 ×1 + 木棍 ×4 + 木板 ×2   |
| 材料清单 | 有序 3×3 | 蓝色染料 ×3 + 纸 ×6             |

摆法：

```
蓝图炮            蓝图桌            材料清单
 L R L             S S P            P P B
 C . C             S S P            P P B
 C C C             . . W            P P B

L = 任意原木（#minecraft:logs，含绯红/诡异菌柄）
C = 煤炭块   R = 红石块
W = 工作台   S = 木棍     P = 任意木板（#minecraft:planks）
B = 蓝色染料
```

「任意原木 / 任意木板」用的是原版标签，所以六种木头（含樱花木、苍白橡木）以及绯红、诡异菌柄都能用。

## 3. schematics 文件夹在哪

模组读写的原理图都放在**游戏目录**下的 `schematics` 文件夹：

- 单机：`.minecraft/schematics/`（启动器多实例则为该实例目录）
- 专用服务端：服务端根目录 `schematics/`

文件夹不存在会自动创建。只识别 `.nbt` 结尾的文件，按名称排序。

> 服务端场景下，客户端 GUI 的文件列表由服务端推送，文件必须真的存在于**服务端**的 `schematics` 目录里才能载入。

## 4. 完整工作流

### 4.1 用蓝图与笔标记区域

1. 手持**蓝图与笔**，右键点击要保存的建筑的**第一个角**，聊天栏提示 `第一个角：x y z`（报的是实际锚定的坐标，即点击面的空气侧）。
2. 点下第一角后，**准星所指的位置会立刻出现半透明的选区预览**，移动鼠标即可看到框到哪里（见第 6.5 节 B）。
3. 右键点击**对角的第二个角**，聊天栏提示 `区域：宽 x 高 x 深`。**框一走开实时预览就消失**，表示选区已经定下来了。
4. 选错了想重来：**潜行 + 右键**任意方块即可清空重新标记（已选满两角时，普通右键也会重新开始；点在已锚定的那个角上只释放该角）。
5. 笔的物品提示会显示当前区域尺寸与总方块数；未选角时显示用法提示。

选区就是两个角之间的**完整长方体**，三个轴各自独立、互不牵制。想框一整栋房子，就点底部的一个面再点顶部的一个面；只想框一块地皮，就点两个高度相同的面。点击哪个面只决定那一格往哪边偏 1 格（取该面的空气侧），不会把选区压扁。

笔是工具，不会耐久损耗也不会被消耗，可以随时用**副手**拿着它——副手拿笔时主手仍可正常放方块，选区预览会切换成琥珀色以作区分。

### 4.2 蓝图与笔的两种模式

对**空气右键**（手上拿着笔、准星没指着任何方块时右键）打开**蓝图与笔菜单**，在菜单里选模式、调朝向，关掉菜单后再去点方块。

| 模式             | 颜色                     | 用途                                                               |
| ---------------- | ------------------------ | ------------------------------------------------------------------ |
| **选区**（默认） | 蓝 / 琥珀                | 标记区域，然后放到蓝图桌里存成 `.nbt`                              |
| **打印目标**     | 绿（已选）/ 黄（准星处） | 指定**一个点**，把**蓝图炮**的打印原点挪到那里，可同时设定打印朝向 |

#### 蓝图与笔菜单

右键空气打开。整个界面分两块：

**模式** — 两个按钮「选区」/「打印目标」，当前模式的那个按钮会变灰（表示已经选中）。

**打印朝向** — 右侧实时显示当前朝向（例如 `90° → 朝 +X`），下面四个按钮：

| 按钮     | 作用                                                         |
| -------- | ------------------------------------------------------------ |
| 左转 90° | 逆时针转 90°                                                 |
| 右转 90° | 顺时针转 90°                                                 |
| 水平翻转 | 开/关前后镜像，按钮文字在 `翻转 [开]` / `翻转 [关]` 之间切换 |
| 复位     | 回到 0°、不翻转                                              |

每次点击都是**累加**的：连点三次「右转 90°」就是 270°，再点一下回到 0°。翻转和旋转互相独立，可以叠加（例如 `flip+90`）。

> 菜单里写着「改朝向会重置蓝图炮的打印进度」——这是刻意的。已经打下去的方块在新朝向下不对应任何位置，继续打会拼出错位的结构，所以改朝向必定停机并重置。

**快捷按键**（不打开菜单也能用）：手持打印目标模式的笔时，<kbd>R</kbd> 逆时针、<kbd>T</kbd> 顺时针、<kbd>F</kbd> 水平翻转、<kbd>G</kbd> 复位。物品栏上方会闪一行当前朝向。按键和菜单按钮效果完全一样。

关闭菜单用 <kbd>Esc</kbd>（等于取消）或点右上角——菜单本身不关闭你的物品栏，只是多了一层控制面板。

**打印目标模式的用法（只需点一个点，不需要框区域）：**

1. 对空气右键打开菜单，点「打印目标」。
2. 在同一个菜单里调好朝向（右转 / 左转 / 翻转），右侧会实时预览结果。调好后关掉菜单。
3. **右键任意一个方块**（取该面朝空气的那一格）。聊天栏播报 `打印原点：x y z —— 现在右键蓝图炮应用`，世界里的那个位置会亮起一个**绿色方块**；准星当前指的那一格是**黄色**，方便你对准。
4. 拿着笔**右键蓝图炮**。聊天栏播报 `蓝图炮打印原点已设为 x y z`，朝向也一并生效。
5. 从此这台炮就从**这一格**开始打印，结构朝菜单里显示的轴向生长，不再是「炮上方一格、居中」。

原理图自带尺寸，所以只要一个原点就够了，不需要再框一个区域。

**改位置不用回头找炮**：第一步绑定过之后，这根笔就记住了那台炮。之后直接右键别的地方，炮的原点会**立刻跟着更新**，不用再跑回去点一次。

取消方式（任选其一）：

- **潜行 + 右键**任意方块 → 清掉已选的原点（同时断开和炮的绑定）。
- 手上没选原点时，右键蓝图炮 → 清除目标，恢复默认位置；炮本来就没有目标时会播报用法。
- 打开蓝图炮 GUI，点最下面那颗长按钮 → 清除目标；没设过目标时点它会把用法发到聊天栏。

打印原点会**随方块一起存盘**，重启世界不用重设。GUI 最下面那颗按钮会显示当前原点（`打印位置：x y z（点击清除）`），没有目标时显示 `打印位置：炮上方（默认）`，按钮下方还有一行设置方法提示。

注意：目标只决定**打印起点**，材料仍然必须从蓝图炮自己的材料槽或贴着它的箱子里取，所以它更适合「炮放在旁边、结构打到远处」这种布线，而不是无限远程施工。区分。

### 4.3 用蓝图桌保存原理图

1. 放置**蓝图桌**，右键打开界面。界面只有一个槽位：「蓝图与笔」。
2. 把标记好区域的笔放进去。
3. 在文件名输入框里填名字（例如 `my_house`），点**保存**。
4. 成功后 `schematics/my_house.nbt` 被写出（自动补 `.nbt` 后缀），聊天栏提示保存了多少个方块。**笔留在槽里，标记的区域也保留**，可以换个名字再存一次。

文件名会做清洗：去掉路径分隔符、非法字符替换成 `_`、自动补 `.nbt`。所以 `../../evil` 只会变成 `evil.nbt`，写不出 `schematics` 目录之外。

单次保存上限 **4,000,000 个方块**（体积 = 长×宽×高），超出会保存失败。

### 4.4 用蓝图炮打印

1. 放置**蓝图炮**，放在你希望建筑出现的**正下方中心位置**（见下方「打印原点」）。
2. 右键打开 GUI。
3. 直接用 `<` `>` 在服务端 `schematics` 目录的文件列表里翻页（或手输文件名），点**载入**。点**刷新**可重新拉取列表。界面会显示「当前原理图：xxx.nbt」。
4. 往**燃料槽**（右上角）放燃料，往 27 格**材料槽**放齐建筑材料（材料也可以放在贴着蓝图炮的箱子里，见第 6 节）。
5. 需要时点开**结构预览**，世界里会出现半透明的待打印结构。
6. 点**开始**。

## 5. 蓝图炮 GUI 说明

界面尺寸 200×364，从上到下：

| 区域       | 内容                                                                                    |
| ---------- | --------------------------------------------------------------------------------------- |
| 右上       | 燃料槽，下方一条橙色燃料余量条                                                          |
| 中部       | 27 格材料槽（3 行 × 9 列）                                                              |
| 文件名     | 输入框 + `<` `>` 翻页 + **载入**；下方显示「第 n / m 个文件」                           |
| 当前原理图 | 显示已载入的文件名，未载入时显示「无」                                                  |
| 状态行     | 状态文字 + 进度条 + `已放置 / 总数 个方块`                                              |
| 按钮区     | 开始/停止、忽略空气、替换方块、速度、重置、刷新；跳过缺料、结构预览、输出清单；打印位置 |
| 下部       | 玩家背包 27 格 + 物品栏 9 格                                                            |

### 按钮

- **开始 / 停止**：切换打印。停止后再点开始会从当前进度继续，不会从头再来。
- **忽略空气 [x]/[ ]**：开启后，原理图里的空气位置直接跳过（默认开启，省事）；关闭则会在那些位置强行放空气，等于清掉目标位置的方块。
- **替换方块 [x]/[ ]**：开启后允许覆盖目标位置已有的方块（默认关闭）。关闭时遇到非空气且不可替换的方块会跳过该位置。
- **速度 n**：在 1 / 2 / 4 / 8 tick 之间循环（默认 4）。数字越小越快。
- **重置**：把进度归零，重新从最底层开始打（不会清空已放置的方块，只是重新走一遍）。
- **刷新**：重新向服务端请求 `schematics` 目录的文件列表。
- **跳过缺料 [x]/[ ]**（默认开启）：材料不够时**不再停下**，而是跳过这些位置继续打后面的，结束时聊天栏汇总跳过了多少。每种材料只会在第一次缺的时候提示一次（`缺少材料 X，已跳过这些位置`）。想让炮一缺料就停，把这个关掉即可。
- **结构预览 [x]/[ ]**（默认开启）：在世界中把还没打印的方块画成半透明彩色方块，见第 6.5 节。
- **输出清单**：把「还需要多少材料 / 已经有多少」写进一个**材料清单**道具（优先刷新背包里已有的那本），见第 6.6 节。
- **打印位置**（长按钮）：显示当前打印原点。没设过目标时是 `打印位置：炮上方（默认）`，设过则是 `打印位置：x y z（点击清除）`。**设过目标**时点一下清除、恢复默认；**没设过目标**时点一下会把完整用法发到聊天栏（不会毫无反应）。用蓝图与笔的「打印目标」模式设置，见 4.2。

> 炮的 GUI 上**没有**旋转和翻转按钮。朝向由蓝图与笔设定，用笔点一个打印位置时一并交给炮。这样「哪边说了算」永远只有一个答案。

### 打印朝向（旋转 / 水平翻转）

蓝图炮可以把结构**转着打**，不必迁就它的原始朝向。朝向**只在蓝图与笔上设定**：

- **蓝图与笔菜单**：对空气右键打开，里面直接有左转 / 右转 / 翻转 / 复位，右侧实时显示结果。
- **快捷按键**：手持**打印目标**模式的笔时，<kbd>R</kbd> / <kbd>T</kbd> 逆/顺时针旋转、<kbd>F</kbd> 翻转、<kbd>G</kbd> 复位。

调好后**右键蓝图炮**，位置和朝向会一起应用。炮的 GUI 只显示当前朝向，不能改。

两点行为需要注意：

1. **变换的是「坐标 + 方块朝向」两件事**，不只是把方块搬过去。楼梯、熔炉、原木这类有朝向的方块会跟着转，所以转 90° 之后房子看起来还是正着放的，不是一堆朝向错乱的方块。没有朝向属性的方块（石头、木板等）不受影响。
2. **改朝向会重置打印进度**。已经放下的方块位置在新朝向下不再对应任何一格，继续打只会把旧朝向的残迹和新朝向混在一起，所以脚本会**停止当前打印并清空进度**，聊天栏会明确告知。摆放前先定朝向，别打到一半再转。

判断朝向看哪里：GUI 最下方一行、以及蓝图与笔的物品提示栏都会显示 `朝向：90°，结构朝 +X 生长`。冒号前的角度是你转了多少，`+X / -X / +Z / -Z` 是**结构自身的「北」现在指向世界哪个轴向**——也就是结构往哪边长。初始是 `0° -Z`。

朝向和打印原点一样，**会随方块存盘**，重启世界后保持。

### 状态文字

| 显示         | 含义                               |
| ------------ | ---------------------------------- |
| 未载入原理图 | 还没载入任何文件                   |
| 就绪         | 已载入，等待开始                   |
| 建造中       | 正在打印                           |
| 燃料耗尽     | 燃料槽空了，补燃料后重新开始即可   |
| 缺少材料     | 材料槽里找不到下一个方块所需的物品 |
| 建造完成     | 全部方块处理完毕                   |

### 聊天栏提示

GUI 状态文字之外，所有「打不下去」的原因都会同时发到**聊天栏**：发给正在操作界面的玩家，以及蓝图炮 24 格内的其他玩家。完全相同的消息 10 秒内只发一次，不会因为卡住而刷屏。

| 触发                     | 聊天栏输出                                                                                                                      |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| 载入成功                 | `蓝图炮：已载入 xxx.nbt（N 个方块，WxHxD）`                                                                                     |
| 载入失败                 | `蓝图炮：无法载入 xxx.nbt —— <原因>`，原因为「schematics 目录中找不到该文件」「不是有效的 .nbt 原理图文件」「文件名不合法」之一 |
| 点开始但没载入           | `蓝图炮：尚未载入原理图，请在输入框填写文件名后点载入`                                                                          |
| 点开始但已打完           | `蓝图炮：该原理图已建造完成，需要重置后才能再次开始`                                                                            |
| 开始 / 暂停              | `蓝图炮：开始建造 xxx.nbt` / `蓝图炮：已暂停（已放置 N 个方块）`                                                                |
| 燃料槽空                 | `蓝图炮：燃料耗尽，请在燃料槽补充燃料后重新开始`                                                                                |
| 燃料槽里是不可燃物品     | `蓝图炮：<物品名> 不能作为燃料`                                                                                                 |
| 缺材料（开「跳过缺料」） | `蓝图炮：缺少材料 <物品名>，已跳过这些位置`（每种材料只提示一次，打印继续）                                                     |
| 缺材料（关「跳过缺料」） | `蓝图炮：缺少材料 <物品名>，已停止`                                                                                             |
| 建造完成                 | `蓝图炮：建造完成，共放置 N 个方块`；有跳过的会追加「跳过 M 个被阻挡的位置」「跳过 K 个缺材料的位置」                           |
| 蓝图桌保存成功           | `蓝图桌：已保存 xxx.nbt（N 个方块）`                                                                                            |
| 蓝图桌保存失败           | `蓝图桌：保存失败 —— <原因>`，原因为「缺少蓝图与笔」「尚未标记区域」「未填写文件名」或具体异常信息（如区域超过 400 万方块）     |

「跳过 M 个被阻挡的位置」只统计两种情况：目标位置已有方块且没开「替换方块」，以及基岩这类不可破坏的方块。开了「忽略空气」时跳过的空气不计入。

## 6. 打印规则（重要）

### 打印原点

默认打印区域从**蓝图炮正上方一格**开始，水平居中对齐蓝图炮：

```
origin = 蓝图炮坐标 + (-floor(sizeX/2), +1, -floor(sizeZ/2))
```

所以在放蓝图炮之前先想清楚建筑的水平中心。奇数尺寸时建筑中心线穿过蓝图炮那一列，偶数尺寸会偏半格。

**用蓝图与笔的「打印目标」模式可以覆盖这个原点**（见 4.2）：此时 `origin` 直接等于你右键点出来的那一格，蓝图炮不必待在建筑底下。原点会随方块存盘，GUI 底部按钮可一键清除回默认。

### 打印朝向

在默认朝向（`0°`，不翻转）下，原理图里的每一格相对原点的偏移就是它自己的 `(x, y, z)`。开了旋转或翻转之后：

```
实际偏移 = 变换(该格的 x, z) 横向，y 不变
```

坐标和方块朝向**都委托给原版**做，不自己写公式。具体是调用存档结构方块用的那套：

| 用途                             | 调用                                                                |
| -------------------------------- | ------------------------------------------------------------------- |
| 相对坐标绕原点旋转 + 镜像        | `StructureTemplate.transform(pos, mirror, rotation, BlockPos.ZERO)` |
| 角点修正，让变换后仍贴着原点     | `StructureTemplate.getZeroPositionWithTransform(...)`               |
| 尺寸换算（仅 90°/270° 交换两轴） | `StructureTemplate.getSize(Rotation)`                               |
| 方块朝向属性                     | `state.mirror(mirror).rotate(rotation)`                             |

**顺序是先镜像、后旋转**，和原版 `StructureTemplate.placeInWorld` 里写的一模一样。

同时**每个方块的朝向属性也会一起转**（`facing` / `axis` / `rotation` / `orientation`），所以楼梯、熔炉、原木不会朝向错乱。这一步交给原版的 `BlockState.rotate(Rotation)` 完成，它自己知道每个方块哪些属性该转——没有任何朝向属性的方块（石头、木板等）自然就原样返回，不需要我们去判断方块类型。

90° 与 270° 会**交换水平两轴的尺寸**：一个 `3×5` 的原理图转 90° 后占地是 `5×3`。默认原点（炮上方居中）用的就是这个变换后的尺寸，所以转完不会偏心。

> **历史提示**：v1.0.0 之前是自己手写坐标公式的（`mx = 翻转 ? -x : x` 再旋转），那套是**错的**——翻转翻错了轴（`LEFT_RIGHT` 应该翻 Z 轴），而且旋转没有 pivot，导致 90° 时把方块放到了包围盒外面。现在是纯委托，别再手写回来。

这套逻辑有一个独立的自检脚本，改完变换逻辑可以跑一下：

```
python3 tools/transformcheck2.py    # 权威：包围盒、双射、对合、Z 轴镜像，全矩阵覆盖
python3 tools/vanillacmp.py         # 复盘用：旧实现 vs 原版的差异记录
```

### 打印顺序

与 Create 一致：**自下而上逐层**，每一层内按 x 再按 z 推进。也就是说先铺地板再砌墙最后封顶，不会出现悬空方块先放的情况。

### 消耗

- **材料**：每个方块扣 1 个对应物品（按 `方块.asItem()` 匹配）。找不到时——开了「跳过缺料」就跳过去继续打，没开就停下并报「缺少材料」。
- **燃料**：每成功放置 1 个方块消耗 **8 tick 燃料**（燃料值取游戏内 `fuelValues`，煤炭 1600 tick ≈ 200 个方块，岩浆桶 20000 tick ≈ 2500 个方块）。燃料耗尽永远会停（和跳不跳过缺料无关）。
- **创造模式玩家开炮则全部免掉**：不扣材料、不烧燃料，纯粹按原理图摆放方块。**没有开关也不用手点**——按「开始」的那位玩家处在创造模式就自动生效，状态栏会显示「（创造：不消耗）」。生存模式玩家按开始则正常消耗。

### 材料来源（27 格材料槽之外）

找材料时的顺序是：**先扫蓝图炮自己的 27 格材料槽，再扫紧贴蓝图炮的 6 个方块**。

相邻容器支持两类：

1. 原版容器（箱子 / 大箱子 / 桶 / 潜影盒 / 漏斗 / 发射器等）——直接读它的物品栏，箱子会正确处理「大箱子合并」和方向限制；
2. 其他模组的容器——走 NeoForge 的 `Capabilities.Item.BLOCK`（物品处理器）取物。

所以标准的用法是：**蓝图炮旁边放几个箱子装满材料**，炮就能连续打印，不用盯着 27 格槽位补货。材料清单里统计的「已有」数量同样包含相邻箱子的库存。

### 会自动跳过的方块

以下情况**不消耗材料也不消耗燃料**，直接跳到下一个：

1. 原理图里是空气，且开了「忽略空气」；
2. 目标位置已有方块、不可替换，且没开「替换方块」；
3. 目标位置是不可破坏的方块（基岩、末地传送门等，`getDestroySpeed < 0`）；
4. 目标位置的方块状态和原理图要求的**已经完全一致**（避免重复施工浪费材料）。

### 其他

- 打印时会把原理图里记录的**方块实体数据**（箱子内容、熔炉、告示牌文字等）合并写入放置出的方块实体。数据损坏不会中断打印，只会跳过该条。
- 蓝图炮被挖掉时，容器内的所有物品会掉落在地上。
- 已载入的文件名、进度、材料槽内容都会随方块一起存档；重进游戏或重启服务器后会自动按文件名重新读取 `schematics` 里的文件（文件被删了会提示载入失败）。

## 7. 支持的 .nbt 格式

读取时同时兼容两种主流写法，gzip 压缩与未压缩都能读：

1. **Create / Schematica 风格** —— 每个 block 条目自带完整的 `state` compound：

```
root
├── size: int[3]
├── blocks: list
│   └── { pos: int[3], state: {Name:"minecraft:stone", Properties:{...}}, nbt: {...} }
└── entities: list
```

2. **原版结构方块风格** —— `palette` 列表 + `state` 下标：

```
root
├── size: int[3]
├── palette: list of {Name:..., Properties:...}
└── blocks: list of { pos: int[3], state: <palette index>, nbt: {...} }
```

保存（蓝图桌）统一写出第 2 种格式（palette + index）的 gzip NBT，且**只记录非空气方块**，同时写出空的 `entities` 列表。

因此机械动力、Schematica、Litematica 导出的原理图，以及游戏内结构方块保存的 `.nbt`，都可以直接丢进 `schematics` 文件夹使用。实体（生物、画等）不会被保存或生成。

## 6.5 结构预览

模组的「幽灵预览」渲染器同时负责两件事，都在 `client/SchematicPreview.java` 里：

**A. 蓝图炮的待打印结构**

载入原理图后（默认开启），世界里会在**打印原点**处画出待打印结构的半透明幻影：

- 每个未完成的方块画成一个稍微内缩的半透明立方体，颜色取自该方块的**地图色**（石头发灰、木头偏棕、羊毛是本身的颜色）。
- **已经打到位的方块不再画**：客户端每帧比对目标位置的实际方块状态与原理图要求，一致就跳过，所以预览会随着打印进度自动缩小。开「忽略空气」跳过的空气位置不在预览里。
- 相邻方块之间的内部面会被剔除，只画外壳，不会糊成一团。
- 性能保护：只画距相机 **96 格**以内的方块，每帧最多 **8000** 个立方体；载入时若结构超过 **40000** 个方块，预览只取前 40000 个（聊天栏会提示），打印本身不受影响。
- **结构预览 [x]/[ ]** 按钮是纯客户端开关，随时可以关掉；换世界 / 换维度 / 退出服务器会自动清空缓存。
- 预览数据由服务端在载入原理图和打开 GUI 时推给附近的客户端，多人游戏里每个玩家都能看到自己那份。

**B. 蓝图与笔正在拉的选择框**

用蓝图与笔点下**第一个角**之后，准星指着的方块面会立刻出现半透明选区：

- 选区**随准星逐帧更新**，不用等到点第二个角才知道框到哪；**第二个角一旦确定，实时框立刻停止跟随**，不会继续黏着准星假装选区还没定。
- 选区就是两个角之间的**完整长方体**，三轴各自独立。想把房子整个框进去，就点底部的一个面和顶部的一个面 —— 高度会照实算进去，不会被压成一层。
- 颜色区分手持与模式：**主手**蓝色（`#4A80FF`）、**副手**琥珀色（`#FFB03A`）、**打印目标模式**绿色（`#5BE08A`）。副手拿笔时主手可以正常放方块。
- 打印目标模式下**不画选区框，只画两个单格标记**：绿色 = 已确定的打印原点，黄色（`#FFD84A`）= 准星当前指的那一格，也就是下一次右键会确定的位置。
- 两个角都取「被点击面的空气侧」那一格，点击**哪个面**因此只影响 1 格的偏移，不影响选区是否立体。
- **预览与提交完全一致**：实时框和第二次点击存的角用的是同一个函数，松手那一刻框不会跳变。
- 相邻面会消隐，整个选区读起来是一个半透明的实心盒子而不是线框。
- 性能保护：体积超过 **40000** 格时只画 **2 格厚的外壳**；超过 **400 万**格直接不绘制（那种尺寸的框只会糊满屏幕）。
- 选区状态在**客户端与服务端同步维护**：`useOn` 在两边都记账，客户端因此能零延迟画出来，不掉包、不抖动。
- 清除方式：**潜行 + 右键**清空整个选区；点在已锚定的那个角上则只释放该角。
- 该状态是纯客户端的，不消耗耐久、不产生网络包。

## 6.6 材料清单道具

点 GUI 里的 **输出清单** 按钮后：

- 如果背包里**已经有**一本材料清单，直接刷新它的内容；否则新建一本放进背包（背包满了就掉在蓝图炮旁边）。
- 清单统计的是**当前进度之后**还需要的材料（已完成的部分不再计入）。
- 每种材料记录「需要 N」和「已有 M」，已有数 = 蓝图炮 27 格材料槽 + 相邻 6 个容器里的库存。**已有 ≥ 需要**显示为「够」，否则显示「缺」。
- **右键**使用即可打开分页界面：显示原理图名、总进度（`已收集 X / Y`）、每行的物品名与 `已有 / 需要（够/缺）`，可翻页（每页若干行）。
- 物品提示栏也会显示 `原理图：xxx（N 种材料，已收集 X / Y）`。
- 清单最多记录 300 种材料；空清单会提示是由蓝图炮生成的。
- 聊天栏会播报 `蓝图炮：已输出材料清单（N 种材料，共需 M 个）`；没载入原理图或已打完时提示没有可输出的内容。

## 8. 常见问题

**Q：点开始没反应 / 一直显示「未载入原理图」**
先在输入框确认文件名、点**载入**。若提示载入失败，检查 `schematics` 目录位置（服务端要放在服务端根目录）以及文件是否带 `.nbt`。

**Q：显示「缺少材料」**
材料槽里缺下一个方块对应的物品，聊天栏会点名缺的是哪个。注意是按物品匹配：台阶、楼梯、染色方块、朝向不同的方块各不相同。

**Q：显示「燃料耗尽」**
燃料槽补上任意有燃烧值的物品（煤炭、木炭、木板、岩浆桶等），重新点开始。放错东西（比如石头）聊天栏会直接说它不能作为燃料。

**Q：打印出来朝向不对 / 位置不对**
朝向在**蓝图与笔**上设定（菜单按钮，或手持打印目标模式的笔按 <kbd>R</kbd>/<kbd>T</kbd>/<kbd>F</kbd>/<kbd>G</kbd>），设好后**右键蓝图炮**才会应用；炮的 GUI 上没有朝向按钮，它只显示当前值。详见第 5 节。如果楼梯、熔炉这类方块朝向是对的、但整体偏了一格，那是**打印原点**的问题不是朝向，用蓝图与笔的「打印目标」模式重设原点。

**Q：改了朝向，正在打的进度没了**
这是故意的。改朝向时已放置的方块在新朝向下不再对应任何位置，程序会停止打印并清空进度，避免新旧朝向混在一起。摆放之前先定朝向。

**Q：蓝图桌保存失败**
常见原因：没放笔、笔没标记完两个角、没填文件名、区域超过 400 万方块。具体原因会发到聊天栏。

**Q：笔会被用掉吗**
不会。笔是工具，保存后仍留在蓝图桌里，标记的区域也保留，可以换个文件名再存一份。

**Q：能不能打印超大建筑**
能，但速度档位最快也是每 tick 8 个方块，且需要消耗对应材料与燃料。建议先拿小建筑试。

```
└── src/main/java/com/schematicannon/...
```

前置：JDK 25（`gradle.properties` 里的 `org.gradle.java.installations.paths` 指向 `D:\Projects\minecraftMods\_tools\jdk25\jdk-25`；这是仓库外的本地目录，不入库）。

```
cd schematicannon
./gradlew jar          # 产出 build/libs/schematicannon-1.0.0.jar
./gradlew runServer    # 起一个测试服务端验证加载
```

### 改完模型 / 材质后怎么打包

仓库有两套等价的打包脚本，功能完全一致，按你的终端环境选一个：

| 环境                                       | 脚本             |
| ------------------------------------------ | ---------------- |
| Windows PowerShell（推荐，Windows 上原生） | `tools\pack.ps1` |
| Git Bash / WSL                             | `tools/pack.sh`  |

**PowerShell 版：**

```powershell
.\tools\pack.ps1                              # 五阶段完整流程
.\tools\pack.ps1 -Check                       # 只做校验，不编译（改完模型先跑这个，秒级）
.\tools\pack.ps1 -Quick                       # 跳过预览图生成
.\tools\pack.ps1 -Preview                     # 只出预览图
.\tools\pack.ps1 -Dist D:\some\dir            # 打完顺便复制到该目录
.\tools\pack.ps1 -Online                      # 联网解析依赖（默认离线）
.\tools\pack.ps1 -NoVerify                    # 跳过 jar 内容比对
```

> 若提示「禁止运行脚本」，用
> `powershell -ExecutionPolicy Bypass -File tools\pack.ps1`
> 或先执行 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`。

**Git Bash 版：** 把上面的 `-Check` / `-Quick` / `-Preview` 换成 `--check` /
`--quick` / `--preview`，`-Dist D:\some\dir` 换成 `--dist /d/some/dir`。

两个脚本都从 `gradle.properties` 的 `mod_version` 读取版本号，jar 名自动拼成
`schematicannon-1.0.0.jar`。

脚本依次做五件事（任一失败即中止，退出码非零）：

1. **校验模型** —— JSON 可解析；每个 `element` 旋转后的 AABB 仍在 `[0..16]`；
   旋转角必须是 **22.5 的倍数**；贴图变量能解析到真实文件。
2. **校验贴图** —— 每张必须是 **16×16** 的真彩色 PNG；模型里引用的贴图必须存在；
   顺手列出没被任何模型引用的孤儿文件（贴图重命名后最容易漏这一步）。
3. **生成预览** —— `textures_sheet.png`（贴图拼版）和 `model_preview.png`
   （白底等轴测渲染），不用进游戏就能看效果。
4. **编译打包** —— 跑 `gradlew jar`，把产物复制成仓库根的 `schematicannon-1.0.0.jar`。
5. **校验 jar** —— 逐张比对 jar 内与磁盘上的贴图字节数，并比对模型 JSON 的 md5，
   确认打进去的确实是最新素材（防止 gradle 缓存没刷新）。

> **Windows 上改 `pack.ps1` 的注意事项**：文件必须保存为 **UTF-8 with BOM**。
> Windows PowerShell 5.1 会按 ANSI（GBK）代码页解析没有 BOM 的脚本，
> 中文注释全部变乱码，还会连带报出一堆假的引号不匹配语法错误。

贴图只需要放进 `src/main/resources/assets/schematicannon/textures/{block,item}/`，不用改代码。

模型各面与贴图变量的对应关系：

| 材质变量               | 贴图                                       | 用在                               |
| ---------------------- | ------------------------------------------ | ---------------------------------- |
| `#stone`               | `block/schematicannon_stone`               | `base` 底座（单层）                |
| `#wood` / `#wood_side` | `block/schematicannon_wood` / `_wood_side` | `deck` / `bed` 木台                |
| `#metal`               | `block/schematicannon_metal`               | `barrel_core` 炮管主体             |
| `#shaft`               | `block/schematicannon_metal_shaft`         | `muzzle` / `breech` 炮口与炮尾     |
| `#ring`                | `block/schematicannon_metal_ring`          | `ring_1..4` 四道外凸环箍（亮钢色） |
| `#accent`              | `block/schematicannon_left_right`          | `axle_west` / `axle_east` 轮轴     |
| `#particle`            | `block/schematicannon_wood_side`           | 破坏粒子                           |

未再被引用的遗留贴图：`block/schematicannon_top`、`block/schematicannon_bottom`、
`block/schematicannon_front_behind`（旧方块模型专用）。打包时脚本会把它们列出来提醒。

其余贴图：

| 贴图                                             | 用在                        |
| ------------------------------------------------ | --------------------------- |
| `block/schematic_table_top`                      | 蓝图桌顶面（图纸 + 羽毛笔） |
| `block/schematic_table_side`                     | 蓝图桌其余五面              |
| `item/material_list`、`item/schematic_and_quill` | 两个道具图标                |

> 贴图绘制注意：**方块面贴图不要描 1px 深色边框**。那是道具图标的画法，
> 方块面是平铺的，边框会变成一格一格的深色接缝。

另外 `schematicannon/gen_textures.py` 是**最初那套贴图的程序化生成器**（Python 3 + zlib，无第三方依赖）。现在贴图已经手工精修过，**这个脚本不要再跑**，否则会覆盖掉手改的素材；留着只是记录初始素材怎么来的。

## 10. 已知限制

- 不支持偏移调整，打印位置由蓝图与笔的「打印目标」模式指定（默认是炮上方一格居中）。
- **支持旋转（4 个 90° 档位）与水平翻转**，但只在水平面上；不支持竖直方向的翻转或倾斜。
- 不保存 / 不生成实体（生物、盔甲架、画、掉落物等）。
- 蓝图炮没有多方块模型，也不吃机械动力的应力/转速系统。
- 客户端 GUI 是纯代码绘制的简洁界面，没有复用 Create 的贴图资源。
- 方块各面用的是**独立贴图**（顶 / 底 / 左右 / 前后），没有做连接纹理，相邻摆放时接缝是硬切的。
- 结构预览画的是**按方块地图色着色的半透明方块**，不是真实方块模型，所以看不出纹理与朝向细节。
- 蓝图与笔的选区高亮只在**客户端**计算，不改动服务端逻辑；它不会显示每格方块的真实内容。
- 大型原理图打印时会持续占用服务端 tick，速度档位建议保持默认 4。
